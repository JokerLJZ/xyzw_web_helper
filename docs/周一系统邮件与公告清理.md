# 日常任务：周一领取并删除系统邮件与游戏公告

分析日期：2026-10-18。配置键mondayMailCleanup，所有默认值均为false；用户开启后，只在执行日常任务且服务器北京时间为周一时运行。此开关不创建额外定时计划；单账号、批量日常和已有定时日常均共享DailyTaskRunner。

## 当前客户端与协议依据

沿public/game/index.html、game-defines.a175e.js、main.2a00e.js确认manifest POST、CDN转换与XXTEA解密实现。重新请求platform=hortor、version=0.36.0-android，确认game=b72ac、launcher=91d6a、协议=c5e7c、配置0c3a7d906d，与检查的内容寻址资源一致。

| 调用链 / 模型 | 核实结果 |

| 分类 | EMMailCategory.categorySystemMail=0、categoryDailyMail=4、categoryPublicNoticeMail=5；本次只传[0,5]，不处理每日邮件或战报 |

## 执行与确认

- 单账号日常设置、批量账号设置及日常模板增加“周一领取并删除系统邮件与公告”，默认关闭，旧账号缺少字段也视为关闭。
- 按本账号WebSocket最近服务端时间判断北京时间周一；服务端时钟缺失时使用执行器当前时间。非周一不发邮件请求，中途停止或跨出周一不再发送后续操作。
- 查询系统邮件与公告。有附件且state<3时先领取，必须从响应mail状态或补查确认state>=3，才删除该封邮件。无附件或已领取邮件可直接删除。收到每日邮件或其他类别时停止，避免超出范围。
- 写请求结果不明确或超时，先查询邮件状态，不直接重发领取或删除。删除补查时，只有完整列表left=0且目标已消失，才把缺失当作删除确认。
- 每次处理当前首批最多60封，处理完重新读首批；不猜测未核实的翻页游标。最多100批，删除后同一邮件仍出现则报未确认，不无限循环。没有邮件正常完成；同一周一重复运行仅处理当前剩余邮件，不需靠本地标记假定服务器已处理。
- 复用连接池和日常请求间隔，附件奖励的role增量合并进本账号快照，保持后续日常库存核对一致。原“领取邮件奖励”配置保持原行为。
