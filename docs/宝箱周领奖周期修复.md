# 宝箱周领奖周期修复

分析日期：2026-10-17。

## 当前资源与证据

从public/game/index.html及main.2a00e.js读取启动链：POST `/login/manifest?platform=hortor&version=0.32.0-android`，按convertAssets转换到官方remote目录，再按loadJscAndDecode的XXTEA规则解密。重新请求manifest并下载game资源，game=22c3b、launcher=861b5、协议TEST_REMOTE_MODULE=dcdf9、配置dataBundleVer=0c3a7d906d。当前game与同日分析资源内容一致。

客户端ActivityTimeModule.getWeekActRoundInfo读取ROLE.statisticsTime中的week:act:cr:cnt:<typ>，查SERVER_DATA.activity中对应活动的openTime/endTime（毫秒），仅当统计时间（秒）落在活动起止范围内时计入已领轮数。不是按本机最近一个周五清零。

UI ActivityTimeRoundRewardConfirmDialog确认后调用module.claimWeekActReward，再由ActivityService.claimWeekActReward发送typ及selectRewardsMap。现有项目实际指令为activity_claimweekactreward，本次没有改动协议注册或奖励选项。宝箱typ=2，六种选项共用同一领奖轮数判断，故错误不局限于珍珠。招募周、黑市周在tasksItem中没有使用此次移除的周五清零函数。

## 修复与验证

src/utils/batch/tasksItem.js改为依据activity_get返回的该账号活动窗口判断统计是否跨期，保留秒/毫秒统计时间兼容。窗口缺失或无效时保留服务端计数，避免制造漏领轮数。领奖后重新查询活动，并用同一窗口核对角色统计。沿用逐账号查询、请求成功后核对、不因3300080盲目重发的流程。

test/smartBoxWeekly.test.js覆盖仍在活动期内的旧日期统计、缺失窗口、真正跨期统计及六种奖励选项的数字Map。全量607项测试通过后新增六种选项回归，专项33项测试全部通过；临时目录生产构建与差异空白检查通过，构建仍有既有大包、worker.js及路由导出提示。未操作真实账号；用户仅提供错误日志，未提供activity_get与角色完整响应，不能保证该错误码仅有这一种成因，也不推定真实领奖响应的完整字段。

后续游戏更新：重新读取manifest，下载匹配哈希资源并按当前loader解密，复查getWeekActRoundInfo及活动起止字段、Service与协议定义；不要复用固定bundle哈希。流程参见game接口定位与更新指南.md。
