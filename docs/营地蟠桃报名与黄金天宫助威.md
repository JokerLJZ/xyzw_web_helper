# 自动报名与黄金天宫助威

核对日期：2026-10-11。接口优先从 `public/game/main.2a00e.js` 的 manifest 与资源加载流程定位，没有查询旧 GitHub API 采集库。

本次分析版本：game `22c3b`、launcher `861b5`、协议资源 TEST_REMOTE_MODULE `dcdf9`、配置 `4921343dff`。实现执行时按当前账号查询 `system_getdatabundlever`，加载对应官方配置，不将这些快照版本写死在业务逻辑里。

## 功能入口

批量任务页面提供自动营地报名、自动蟠桃报名、批量黄金天宫助威；定时任务选择器也提供这三项。未添加到每日任务。

两种报名不需要额外参数。黄金天宫助威需要先用选中账号刷新候选俱乐部，再手动选择目标；所有选中账号本期各助威一次。定时任务独立保存俱乐部和期次，跨期须重新刷新选择，避免自动沿用旧期目标。

## game 中的定位路径与接口

| 功能 | 客户端路径 | 查询与操作 |
| --- | --- | --- |
| 营地报名 | ClubWarSignUpData.buttonStatus → ClubWarModule.sendSignup → ClubService.signup | `club_getinfo`、`role_getroleinfo`、`legion_getinfo`；写入 `club_signup`，参数 `{}` |
| 蟠桃报名 | LPSignUpDialog.onClickSignUpBtn → LegionPayloadModule.sendPayloadSignup → LegionService.payloadSignup | `legion_getpayloadlegioninfo`、`role_getroleinfo`、`legion_getinfo`；写入 `legion_payloadsignup`，参数 `{}` |
| 黄金天宫助威 | LegionWarSeasonOutStage4Data.getBetList / sendCheer → SaltRoadService | `saltroad_getseasonoutrank`；写入 `saltroad_outcheer`，参数 `{ legionId }` |

在解密的协议资源中，服务注册器 `_gs` 将服务名与方法组合为小写指令；同时核对了对应指令定义与响应模型，未仅凭方法名猜指令。

现有营地按钮原先发送 `legionmatch_rolesignup`，它是另一套个人排位报名接口。本次改为当前营地的 `club_signup`。

## 条件与状态确认

- 营地：客户端周五至周日为报名阶段。仅会长／副会长可报名；读取当前赛季配置检查人数、成员总战力、本周签到。`club.phase` 在报名阶段应晚于本周一，表示下一轮已报名。
- 蟠桃：根据 PayLoadScheduleConf 确认比赛日，再按 PayLoadConstant.regTime / regLast 推导报名窗口。本次配置为比赛日 08:00–18:00（北京时间）。仅会长／副会长、俱乐部未锁定且人数／铃铛达标时报名。铃铛门槛按客户端的首次月赛日期、赛季计算和 lingdangLimit 推导，不自动购买铃铛。`legion.statistics['payload:war:sign:up']` 等于当日期次表示已报名。
- 黄金天宫：根据当前赛季的瑞士轮配置推导窗口，起点为第二轮日期的次日 00:00，终点为第三轮日期 19:55；统计键的期次取第一轮日期。候选俱乐部按 `sOWinCnt` 降序取前 64，符合客户端 `getBetList`。`role.statistics['sr:out:cheer:<期次>']` 保存已选俱乐部，已助威账号不重复或更换目标。当前接口没有数量参数。

写入成功后重新查询服务器状态确认；失败不自动重复报名或助威。缺失关键数据时停止或跳过，并在日志说明原因。

## 测试与更新

`test/signupCheer.test.js` 使用当前配置的精简快照，覆盖报名条件、权限、重复执行、时间边界、跨期、目标筛选、请求失败、协议编码及连接清理。响应结构来自当前客户端协议模型；尚未用真实账号在线报名或助威。

游戏更新时按 [game接口定位与更新指南](game接口定位与更新指南.md) 重新获取 manifest 并检查上述类、Service 和配置。尤其核对赛程类型枚举、报名权限、统计字段与助威次数；未知赛程配置会跳过，需检查后适配，不能直接增加重试。
