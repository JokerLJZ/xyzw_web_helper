# 黑市采购清单响应兼容修复

分析日期：2026-10-13。

## 报错位置与限制

“黑市采购配置不完整，未下发修改”出自syncBlackMarketPurchaseConfig读取store_getpurchase响应后的字段检查。此时本地用户清单已通过非空检查，还没有发送store_setpurchase。因此它不表示用户没有保存清单。用户日志未包含响应正文，不能断言该账号具体缺少哪个字段。

## 当前客户端证据

从public/game/index.html进入main.2a00e.js，按loadRemoteBundleVers实际请求头与空请求体POST manifest：platform=hortor、version=0.32.0-android。按convertAssets转换CDN地址，以loadJscAndDecode中的XXTEA实现单独解密资源。本次版本game=22c3b、launcher=861b5、TEST_REMOTE_MODULE=dcdf9、config=78fbc、codeVersion=2.48.2、dataBundleVer=1a4796cd43。分析副本在/tmp/xyzw-market-fix-{game,launcher,TEST_REMOTE_MODULE}.js，manifest在/tmp/xyzw-market-fix-manifest.json。

| 位置 | 证据 |
| --- | --- |
| game商店面板 | 打开界面调用ShopModule.sendGetPurchase，设置界面编辑goodsData并调用sendSetPurchase |

## 修复行为

读取与写后核验共用响应解析：成功原始对象省略purchaseCnt时补0，省略purchaseItemList时补空数组，匹配官方模型。显式null、负数/小数次数、非数组清单、无效条目或未解包响应不会触发修改。不会把无效字段当作默认值，也不会自动把采购次数改成1。现有采购次数保持不变，已有相同清单跳过；写后重新查询确认次数和清单一致，不一致时报错，不重复写入。手动及定时均通过createTasksStore.store_syncpurchaseconfig使用该流程。

新增17项回归，覆盖省略字段、零次数读回、相同清单不写、无效响应阻止写入和核验失败不重写；相关26项测试通过。全量测试、生产构建结果记于CHANGELOG。未执行真实账号配置或采购。

## 游戏更新后的复查

重新读取manifest并下载对应game/launcher/TEST_REMOTE_MODULE；沿商店界面、ShopModule、StoreService和_gs注册器核对字段、默认值与协议。若本次修复后仍报错，补充store_getpurchase的响应字段结构以区分默认省略与响应布局变更，勿直接绕过检查覆盖采购次数。
