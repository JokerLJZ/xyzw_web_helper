## 执行与结果确认

1. 从当前配置读取种火石ID与每级消耗，拒绝重复等级、非道具支付、零/负数等异常配置。
2. 每账号独立查询`role_getroleinfo {}`和`club_getinfo {}`，核对当前库存、身份与等级。已有道具不足一次时正常跳过。
3. 抽奖前按真实roleId持久化本次库存、费用和预期下一级，发送`club_draw {}`，不传臆造的times/quantity。
4. 每次重新读取完整库存与本人siege，同时确认扣除等于本级消耗、等级按配置前进（最高级回第一级），再清除本次待确认记录并继续。写响应只作指令完成，不当完整库存。
5. 本轮请求上限由进入时库存与当前配置最小费用推导；不会无限追逐外部新增库存。正常结束保留不足一次的零头，日志记录次数、消耗和余额。
6. 超时仅补查不重发；下次执行先核对持久化记录，确认上次结果才继续，仍不明就停止。服务端明确拒绝不重试，已知未消费记录可清除。用户停止或状态校验失败阻止后续抽奖。

批量入口复用现有连接队列、逐账号隔离、500ms指令间隔和定时共享会话；包含此任务的定时组合关闭失败自动补跑，避免不确定消耗被调度器重发。实际服务端响应尚未在线取得，本文的响应字段来自当前官方声明与本地模拟，不声称真实账号已抽奖成功。
