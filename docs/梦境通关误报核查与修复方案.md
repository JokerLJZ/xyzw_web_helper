## 官方流程

当前 game bundle 的 DungeonModule.isDungeonFinished() 直接返回 ROLE.dungeon.id < 0。
getDungeonLevel() 在 id < 0 时显示 DungeonConf.list.length；id == 0 时显示第1层；遇商人时显示 id - 1。
DungeonPanel._checkFinished() 调用 isDungeonFinished() 隐藏怪物；挑战按钮处理器在该判定为真时直接提示并返回，不调用 FightService.startDungeon。
因此负数是明确的通关标记，不能要求 merchant 存在；“当前第200层”也不能等同于“已打完第200层”。本次无需新增协议或改变请求参数。

## 辅助代码问题

src/utils/dreamTaskRunner.js:33 的 isDreamCompleted 把负数判定放在 merchant 检查之后；merchant 缺失时直接返回 false。入口之后又把负数作为梦境层数无效抛出。初始化/阵容选择后重新 fetchRole，也没有在层数校验前重新判定通关。
此外以 id >= 200 直接认定通关不符合当前客户端的明确判定，可能提前结束。maxId 在 UI 中用于最高层展示；它能否独立证明本期完成，本次未取得服务器响应证据，不能无条件套用。
“当前层数 未知”来自异常捕获结果未带 floor，不证明服务器字段缺失。
用户日志未包含原始 dungeon，无法断言该次 id 或 merchant 的实际值。

## 待确认方案

1. 本期梦境中，明确有效的负数 id 按官方完成状态处理，不依赖 merchant、maxId 或阵容。
2. 入口、初始化后的重新查询、每场战斗后的查询统一先判断通关，再做普通层数校验。
3. 普通第200层继续正常流程；不再仅凭 id=200 就跳过。重新审查 maxId 和缺字段加 merchant 的旧兜底，缺少确定证据时重新查询，仍不完整则保留待确认，不能当成通关。
4. 通关显示“梦境已通关，跳过推层”，保留独立采购和现有购买条件；不产生 pushError，也不进入本轮未完成列表；不显示“当前层数 未知”。
