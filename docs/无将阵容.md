# 无将阵容

入口：批量任务 → 阵容管理 → 无将阵容。选择账号后执行，先在已有紫将中按星级升序、等级升序选一名，完全同值按武将ID稳定选择；仅1号位保留该武将，其他位置清空。不会自动合成、培养或重生武将。卸下玩具与宠物，保留物品和宠物本体。

执行前检查拥有紫将和宠物可卸下条件；宠物栏已满时不开始调整，避免调整一半才发现无法卸宠物。所有动作使用当前账号状态，完成后重新查询验证；写超时不直接重发玩具或宠物操作。途中失败可能已完成部分调整，日志如实记录失败，下一次执行会按当前状态重新判断。

## 客户端证据与版本

2026-11-13重新POST当前public/game加载器所用manifest：platform=hortor、version=0.36.0-android；game=03828、launcher=c3d60、TEST_REMOTE_MODULE=66a37、dataBundleVer=da6870e190。通过启动器convertAssets与纯XXTEA实现获取解密业务资源，仅分析，不执行完整业务脚本。

- 武将品质取自当前data/<version>/configc.bin的HeroConf，按本地bonProtocol解码，color=1为紫将。游戏UIHelper.getHeroColor使用Color.ZI紫色、CHENG橙色、HONG红色；当前配置301等为1、201等为2、101等为3。排序使用账号已有hero.star与hero.level，不使用配置初始星级。
- 武将编队复用项目现有applyTargetFormation，使用hero_gointobattle({heroId,slot:0})、hero_exchange({heroId,targetHeroId})、hero_gobackbattle({slot})，以role_getroleinfo.heroes[*].battleTeamSlot验证。官方HeroReplace界面调用HeroService.exchange，记录双方battleTeamSlot并刷新编队。
- 官方LordWeaponModule.sendChangeDefaultWeapon(i=0)调用service.changeDefaultWeapon({weaponId:i})，0为卸下；项目注册与协议资源LordWeapon注册对应lordweapon_changedefaultweapon。写后确认role.lordWeaponId为0。
- 官方PetRoleDataView.PET_EQUIP_SLOT_ID=-1。PetModule._sendLoad调用PetService.load({slotUId})；装备槽拖到空棋盘槽使用空目标槽和默认空字符串uId。发送pet_load({slotUId:{slot:空位,uId:""}})，确认-1无宠物且目标槽uId为原宠物。槽位按petData.unlockedSlot（默认8，最大16）检查，不自动扩容、合成、释放或替换宠物。
- 当前协议注册资源与项目现有CommandRegistry已有上述指令，未根据方法名新增猜测指令。

## 验证与限制

新增回归覆盖星级/等级排序、同值选择、无紫将、宠物栏满、完整卸下、卸下未确认、无需重复卸下、停止与超时不重试。未连接真实账号变更编队。后续游戏更新重新读取manifest和configc.bin，对照品质、slot默认值、编队/卸下操作链及响应字段，再更新测试；不固定本次配置版本或武将ID。
