# 俱乐部大事件奖励领取

## 使用

小号任务增加“领取俱乐部大事件奖励”，对所选账号分别执行，也登记到定时任务白名单。任务只读取榜单、领取已经结束赛事的奖励，不报名、不助威、不消耗道具。复用小号任务连接所有权处理，已有连接和定时会话保留，自建连接释放。

## 执行与边界

每账号先查询角色及首次月赛日期，从当前官方赛程生成候选日期，按最新在前处理。首次日期为空按协议默认没有大事件处理。逐日期跳过已领标记，查询榜单，空榜单跳过；未结束的日期不请求领取。当天赛事结束按20点加配置时长判断；存在多种赛季时长时保守采用该类型最长配置时长，可能比游戏实际开放稍晚。没有时长配置采用客户端isEventWarFinished的4小时备用值，不擅自提前领奖。

领取请求每日期最多一次。请求超时或错误后查询角色，明确统计已领则确认并继续；仍未领或无法查询则停止，不盲目重发。各账号统计独立，失败后继续其他账号。未知榜单结构、无效日期及不完整角色状态拒绝，不当作奖励已经领完。BON省略的空榜单和空统计按当前协议构造默认值处理，显式null仍拒绝。

响应模型来源为公开客户端与协议，未查询真实账号或领取真实奖励；尚无本轮实际服务端响应，不能声称已在线验证。

## 2026-11-23 查询节奏与200400

用户提供200400操作太快日志，原日志无请求命令，尚不能确定发生在连接阶段、榜单查询或领奖。代码原本不是无限重复查询，但对各未领日期查榜单、每次领奖后查角色，入口请求后默认只等500毫秒，可能偏密。当前协议ClaimWarRankRewardResp继承SyncRewardResp，可在返回role.statistics包含该日期明确已领标记时直接确认并合并该标记，不再额外查完整角色；缺少标记或写请求异常仍查角色，不拿缺失字段当已领。

共用请求层每次发送前等待1.5秒，仅只读查询明确200400时额外等待3秒后重查（最多3次）。领奖不自动重发，不因限速把日期记为成功。错误补充命令及日期；连接阶段错误由原连接管理处理。该节奏是本地保守策略，并非服务器公开固定冷却阈值。相关10项测试和临时目录生产构建通过，未线上验证。

按用户后续要求，常规请求层等待从1.5秒改为800毫秒；入口既有请求后等待保留，因此实际相邻请求间隔可能更长。200400查询重查仍等3秒，领奖不重发。相关10项测试通过。
