# 黑市折扣直购刷新上限

分析日期：2026-10-18。

## 资源与调用依据

从public/game/index.html实际加载的game-defines.a175e.js、main.2a00e.js核对manifest POST、CDN转换及loadJscAndDecode的XXTEA实现。重新请求platform=hortor、version=0.36.0-android，返回game=b72ac、launcher=91d6a、TEST_REMOTE_MODULE=c5e7c、配置0c3a7d906d，与检查的已解密内容寻址资源一致。

- 黑市界面刷新按钮调用ShopModule.refreshGood；它先检查SingleShopData.canRefresh，再调用StoreService.refresh({storeId})。当前项目已登记store_refresh、store_goodslist、store_buy及各自响应映射，本次不更换指令或请求参数。
- canRefresh比较config.time + FREE_MARKET_REFRESH祝福总数 + STORE_TIMES权益与currRefresh；currRefresh包含refresh和已使用祝福次数。不能只把商品列表中的refresh和固定次数比较，忽略权益或祝福。
- ShopModule._getGoodList调用StoreService.goodsList({storeId})，从响应goodsList绑定商品并更新refresh；buyGood调用StoreService.buy({goodsId})，成功后合并返回商品列表。SingleGoodData.lastBuyNum为配置limit减serverData.buy_quantity。
- 当前ErrocodeLanguageConf[1300030].chinese为“刷新次数超过上限”。这能确认当前错误码含义；未取得本次真实账号的报错或完整响应，不把其他错误归入刷新用尽。

## 修复行为

折扣直购先购买当前符合折扣设置且未购的商品。只有store_refresh明确返回1300030，才补查一次store_goodslist({storeId:1})。确认商品状态可读且没有符合设置的未购商品时，返回completed，停止剩余刷新；refreshCount为本次实际成功刷新的次数。不会继续重发刷新，也不将该已处理的拒绝写为日常错误日志。

复查失败、商品状态缺失、仍有应购商品、购买失败、其他服务器错误及用户停止仍报告异常，防止误报完成。原采购清单模式保持不变。日常与批量折扣直购复用执行器，因此共享修复。

745项全量测试通过；覆盖本轮购买后刷新用尽、已购商品与超折扣商品混合、剩余应购商品、查询失败、状态缺失、购买失败及日常不产生失败日志。生产构建使用临时目录验证；未使用真实账号执行购买或发送推送。
