# 充值庆典标准任务与兑换

## 使用入口

批量日常 → 副本：

- **充值活动标准任务**：按生日祝福及领奖 → 周年烧烤 → 活动道具抽奖 → 免费福袋及累计充值免费档的顺序运行。可在现有定时任务中选择同名任务；不会自行创建定时计划。
- **查询充值活动兑换物品**：查询已选账号，展示中文物品、每份金道具成本、累计消耗解锁门槛、各账号库存及可兑换份数。输入每账号兑换份数后点击“批量兑换所选物品”。按配置排序依次兑换，每项前重新核对该账号库存与限购。账号切换、活动切期或配置变化后应重新查询。

生日任务每天最多进行两次**具备领取条件的真实任务邀请**，已在当天完成的邀请计入上限。任务的首份奖励先领取，之后按具体任务 ID 邀请，再领取第二份。客户端每个累计祝福任务只允许两份奖励，所以第一天只有一项任务时，不发送没有可领奖任务的第二次邀请。主页面邀请按钮走 `sendCelebrationInvite(0,true)`，只是分享展示，不能用发送两次 id=0 代替完成任务。

烧烤每日 08:00～20:00（中国时区）可挑战。客户端当日总次数为配置 `parameters[1]+1`（含首场免费），任务保留当日剩余3次，同时检查活动总次数、当日开放副本、是否通关及开始战斗状态。跨日、超出挑战时段或次数核验失败后停止该阶段。使用当前已有阵容，不自动更换阵容。

狂欢抽奖每次10抽或1抽，仅使用配置中的普通活动道具。没有活动道具就结束，不用路路通兑换，不自动开启或选择进阶宝箱奖励。每次抽奖后重查该账号库存，必须确认扣除数量。

免费奖励包括周年商店零价格礼包及累计充值 `chargeAmount=0` 档。周年福卡属于付费权益：仅已购账号领取已有可领权益，不购买福卡、不发起充值。已领奖励不会重复领取。

`TEST_REMOTE_MODULE` 的服务注册器 `hue.prototype._gs` 明确以 `(serviceName + "_" + method).toLowerCase()` 建立 wire command。已核对 Celebrate、Activity、Common、Towers 的具体注册列表，不是仅凭方法名推断。

| --- | --- | --- |
| ActivityFestivalCelebrationDialog24 → FestivalModule.sendGetCelebrationInfo → CelebrateService.getCelebrateInfo | `celebrate_getcelebrateinfo {}` | Celebrate_GetCelebrateInfoResp：signCelebrate、fullServerSignCnt |
| 同页面 → sendCelebrationSign → CelebrateService.sign | `celebrate_sign {}` | 同上 |
| ActivityFestivalCelebrationTaskDialog → sendClaimCelebrationTaskReward → CelebrateService.claimPersonal | `celebrate_claimpersonal {idList:[任务id]}` | Celebrate_ClaimResp：celebrateInfoResp及奖励/角色增量 |

| 全服祝福进度条 → sendClaimCelebrationReward → CelebrateService.claimFullServer | `celebrate_claimfullserver {idList:[档位id]}` | Celebrate_ClaimResp |
| ActFestivalTower.sendGetActInfo → TowersService.getInfo | `towers_getinfo {actId}` | Towers_GetInfoResp：towerData（ActGDTowers） |

## 复用设计与状态处理

每个账号先请求 `system_getdatabundlever`，按实际版本加载配置，仅缓存不可变配置。以 actConstantConf 当前活动组0、有效期和开始时间关联 ActFestivalConf，再按玩法类型定位子活动。下一次相同机制活动自动使用新 ID、新价格、新道具和新时间。缺少受支持的子活动则跳过该子步骤；未知机制不能自动视作兼容。

每个账号独立查询领取记录与库存，不共用 tokenStore 中另一个账号的选中角色状态。库存来自完整 `role_getroleinfo`，写响应中的 role 是可能缺字段的增量，不能将缺失库存当作0。每次写后重新查询状态确认；写失败/超时先尽力查询该阶段状态，不盲目重发或自动重试。兑换在结果不明时停止该账号的剩余兑换；标准任务保留错误日志后继续后续独立阶段，整体标记未全部完成。

时间优先读取该账号 WebSocket 客户端 `getServerTime()` 的服务器时钟，尚未获得时以本机时钟为暂时回退。连接走现有队列并在单账号间顺序处理，复用定时账号会话；只清理由本任务取得的连接槽位。

响应模型来自客户端声明，尚未取得真实账号本期返回体。缺失关键快照、库存、次数或写后确认失败时会停止对应操作，可能需要根据真实返回进一步兼容。本次未执行真实账号挑战、抽奖、充值、领奖或兑换。
