# 日常任务完成通知误报修复

## 现象和已确认原因（2026-10-18）

用户反馈批量处理少量账号没有完成日常、没有领取奖励，WxPusher 却提示完成；没有对应账号运行日志。

代码确认：DailyTaskRunner 已在末尾重新读取服务器任务与积分奖励，未完成任务、未领取任务积分和仍可领取的奖励计入 incomplete，批量日常据此设置 pending。然而定时批量外层只累计 failed，所有未失败账号最终直接写 completed，覆盖 pending/stopped。后续其他任务写入同一账号状态，也可能掩盖前面日常的未完成结果。通知组装还将缺失状态默认为 completed，未运行账号可能沿用上一次结果。

这些路径足以解释“未领奖却通知完成”，但没有实际日志，不能确定个别账号没有领奖的原始原因是库存、服务器拒绝、超时或中断。

## 修复

- 每轮先初始化账号状态，逐子任务保留结果，最后汇总；日常 pending 不再被后续成功覆盖。
- 中止、未执行和缺少明确日常结果均不视为成功；纯跳过保留跳过。
- 通知将缺失、等待和运行中状态归为待继续，只有全部账号明确完成才显示成功完成。
- 原有日常服务器核验、领奖间隔和不对不确定写入自动重发的规则不变。本次没有新增游戏请求或改变领奖协议。

用户可对未完成账号再次执行日常，现有执行器会重新读取服务器状态补差。没有授权或使用真实账号执行领奖及推送。

## 验证

回归覆盖真实日常执行器的“请求成功但服务器奖励未领取”结果，经账号汇总及通知后仍为待继续；覆盖后续任务成功、中断、失败、全跳过、无结果及通知标题。实际验证结果记录在根目录 CHANGELOG.md。

## 2026-10-18：条件不具备与附加任务异常不再误判日常失败

用户补充的00:10～00:12日志显示：日/周活跃可领奖励均已领取；竞技场因未到6点跳过；通行证3500020明确提示没有可领奖励；逐鹿盐山竞猜200020查询后未确认生效。旧汇总把这三项合并为未完成，导致已确认完成的日常仍为待继续。

本次为竞技场时间关闭和通行证无奖励返回明确的正常跳过结果，仅在对应命令 `activity_recyclewarorderrewardclaim` 且明确3500020时跳过，不泛化处理其他命令或200020。竞技场仍未完成的服务器任务保留在 remainingTasks 诊断计数，但本次明确按时间跳过的条件不阻塞 dailyIncomplete。已完成但未领任务积分、仍可领取的日/周奖励始终阻塞完成。

日常核心结果与附加任务提示分别汇总：dailyIncomplete决定日常成功/待继续，supplementalWarnings保留附加任务异常；兼容诊断字段incomplete保留总数。批量、定时及单账号界面统一采用核心结果；定时推送在完成清单后另列附加任务提示。真正中断、传输异常、服务器状态无法确认仍会停止或失败，不增加写入重试。
