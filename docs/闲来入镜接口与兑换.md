## 新版胶卷任务协议

| 调用链 | 实际指令及参数 | 声明响应 |
| --- | --- | --- |
| FestivalModule.sendWarOrderGet → ActivityService.warOrderGet | `activity_warorderget {actId:任务活动id}` | Activity_WarOrderGetResp，含activity |
| FiveYearSpecialActivityModule.claimTask → ActivityService.warOrderTaskClaim | `activity_warordertaskclaim {actId:任务活动id,missionId:任务id}` | Activity_WarOrderClaimResp，继承奖励响应并含activity |
| FiveYearSpecialActivityModule.sendPhoto → ActivityService.photo | `activity_photo {activityId:照片活动id,num:本次胶卷数,pieceId:当前片段id}` | Activity_PhotoResp，含activity并继承角色同步响应 |
| FiveYearSpecialActivityModule.claimPhotoReward → ActivityService.claimPhotoReward | `activity_claimphotoreward {activityId:照片活动id,pieceId:当前片段id}` | Activity_RewardResp，含奖励与activity |

协议c5e7c原始注册列表包含 `photo:hb`、`claimPhotoReward:Tb`、`warOrderTaskClaim:nC`；对应构造器 `pb/hb` 导出Activity_PhotoResp、`kb/Tb`导出Activity_RewardResp、`iC/nC`导出Activity_WarOrderClaimResp。注册器 `g3e.prototype._gs` 明确以 `(服务名+"_"+方法名).toLowerCase()` 生成线上指令。反混淆只运行字符串表初始化，搜索结果已对照上述原始注册片段核对。

状态为 `activity.photoActivityInfo[活动id]` 的GDPhotoActivity：默认 `pieceId=0,num=0`；0表示配置排序的第一个片段，-1表示全部完成，其他值必须匹配本期PhotoPieceConf。当前进度达到progressNeed后先领奖，再投入下一个片段。photoCostNum=1，单次投入量为 `min(库存, progressNeed-num)`，不跨片段投入。

任务状态为 `activity.warOrderActivityInfo[任务活动id]`：`complete[任务id]`达completeValue、`taskClaimed[任务id]`不为真时领取。每日以服务器东八区当天起点对dailyTime判断过期；周期名称SEVEN_DAYS虽为七日，`ActFestivalBattlePass.getSevenDaysEndTime` 实际返回 `sevenTime*1000+4*DayDuration`，实现按这个实际规则判定。

实现仅对完整 `activity_get` 查询补省略的协议默认值，明确null/错误结构停止；写响应不当完整快照。每次写后重新查活动，以任务领取标记、投入进度或领奖后下一片段/-1确认。超时只查询，不自动重发；确认失败停止当前账号。照片循环按配置片段数限制次数。

## 已核对的商店调用链

`NewFestivalExchangePage._renderGoods/_doExchange` → `FestivalModule.sendExchange` → `ActivityService.exchange({activityId,goodsId,quantity})`。界面从所属活动 `ActFestivalConf.itemId` 取支付道具，从 `ExchangeActConf` 取商品、价格、数量、限购和解锁门槛。

`TEST_REMOTE_MODULE` 的 `hue.prototype._gs` 将服务名和注册方法组合为小写指令；具体 Activity 注册列表已核对 exchange 方法。协议依据与现有充值兑换一致，详见 [充值庆典标准任务与兑换](充值庆典标准任务与兑换.md)。

| 指令 | 用途与模型 |
| --- | --- |
| `activity_get {}` | Activity快照，读取 `activity.commonActivityInfo[activityId].record` |
| `role_getroleinfo {}` | 账号自己的库存；支付道具 `role.items[itemId].quantity` |
| `activity_exchange {activityId,goodsId,quantity}` | Activity_RewardResp；写响应不能当完整活动快照，重新查询兑换记录确认 |

客户端还检查皮肤是否拥有；已知角色皮肤记录存在时可兑数设为0。未进行真实账号兑换，服务器额外资格限制和实际响应仍需在线验证。

## 使用与实现

副本 →「闲来入镜任务」：领取已完成的每日/周期任务胶卷，使用库存胶卷推进当前片段，领取可领照片奖励，直到胶卷耗尽或全部完成。支持现有定时任务、停止控制和调度器共享账号会话，不自动完成尚未达标的游戏行为。日志只输出活动编码与任务、胶卷、奖励汇总和错误。

副本 →「闲来入镜商店兑换」：逐账号查询两种商店，在弹窗切换「勿忘我商店」或「满天星商店」，查看商品、各账号可兑份数和消耗，填写份数后批量执行。切换商店会清空选择；一次仅兑换当前商店中明确选中的商品。

- `photoActivity.js` 按玩法类型、活动组、名称和完整起止时间关联商店，不绑定本期日期编码。
- `tasksRecharge.js` 复用连接队列、账号隔离、停止和批量生命周期；商店不是无人值守定时任务。
- 每项兑换前重查本账号库存、限购和解锁；配置改变、活动切期、数量不足或结果未确认时停止该账号。写请求超时后仅查询，不自动重发。
- 自动任务已登记副本分组与定时任务映射；商店保持人工选择后执行。

验证：本轮新增6项自动任务测试并扩展传输匹配回归；全量619项测试通过，生产构建到临时目录成功。覆盖每日/周期领取、胶卷不足、先领旧奖励、全部片段完成及重跑不消耗、跨期、写超时不重发、进度未确认即停止、协议默认值与异常结构。仍有既有大包和worker.js缺失提示。未做真实账号运行验证。
