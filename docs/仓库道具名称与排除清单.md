分析日期：2026-10-18。本说明纠正此前把“当期活动专用消费”和“过期后仓库开包”混为一谈的结论。当前活动货币不应尝试使用；活动结束并达到客户端转礼包时间后，符合条件的道具仍通过仓库开包接口处理。

## 新执行规则

1. 仍按库存筛选可能的活动道具，但不再按5000～9999编号直接授权使用；读取账号当前配置版本，按版本缓存config.json和language.json。配置失败不盲目尝试开包，保留名称回退与编号。
2. 按ActFestivalConf关联itemId。普通账号使用start/end；白名单账号使用whiteListStart/end。任一共享道具活动正在开放则跳过，防止一个活动结束而另一个仍在用。
3. 消耗品必须有changePackTime且当前时间严格大于它，等于该时刻也不发送。活动结束不等于立即可开，兑换收尾期以转换时间为准。
4. 需存在直接开包params及对应PackConf。需要选择奖励、参数为空、缺配置、非礼包类道具只显示原因，不能尝试item_consume或猜兑换参数。
5. 已达到上述条件的旧排除道具恢复使用item_openpack({itemId,number,index:0})。复用原分批、限速和超时后查询库存流程，超时不直接盲目重发；用户停止不继续发送。
6. 优先使用本账号WebSocket最近服务端时间，无服务端时钟时使用本地当前时间。活动回顾使用账号服区识别：关联lookBackDay的道具在潜在回顾服、回顾尚未结束或服区无法确认时保留，避免套用旧全服日历。尚未完整移植新服个人回顾排期，宁可明确跳过，不误消耗。

特殊新手币/冲刺箱的转换取决于新手状态，未在本次增加通用自动处理。ext.expireTime/claimTime不代表ItemConf.changePackTime，不据它们直接授权使用。
