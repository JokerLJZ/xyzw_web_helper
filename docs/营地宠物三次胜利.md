# 自动营地：宠物补齐当日共享成功次数

## 2026-10-14最终规则

用户确认宠物与据点共享成功次数上限，本实现以服务器当日 `siege.attackMap[日期].aSuccessCnt` 为成功进度。默认目标为当日累计3次成功：据点已成功1次，转宠物后只补2次；已有2次只补1次；已达3次不再攻击。此前“宠物独立再打三场、不计入共享成功次数”的说明已被本规则替代。

低战力据点优先，连续三次未获胜后转宠物；无可挑战据点或据点免费出手耗尽也转宠物。不消耗双倍道具，不更改当前攻击阵容，不自动购买或使用特权。有效特权按官方配置放宽据点出手上限，但默认成功目标仍为3次，没有新增自动打满特权5胜选项。

## 对账与恢复

每场攻击后查询club_getinfo并读取共享成功次数。成功响应按isWin与成功增量对账，普通据点还要求出手恰好增加1次；宠物出手是否增加不作猜测，但成功必须对应共享计数增加1次。结果缺失、计数回退、胜负矛盾均停止。

超时或网络错误后查询状态与战报，只有唯一新增且匹配目标/镜像的战报、共享成功增量一致（据点出手增量也一致）才继续；无法确认不重发。13000070仅在计数和新增战报均未变化时按官方目标冲突流程刷新目标阵容并重选，最多连续重选3次。其他成员打败或改变目标难度时重新选人，不直接结束整账号。

重新执行直接读取服务器当日共享进度补缺，已达标时只补领奖，返回战报不完整也不会因宠物记录较少而多打。每个账号独立查询状态，保留串行执行、连接槽位清理、停止及跨日控制。

## 领奖与限制

成功次数目标达标后查询营地任务，领取所有当前配置下已达标、未领取、可见的奖励，每档领取后重查taskClaimedMap。请求超时但查询确认已领可继续；未确认则报错且不重复发送。省略默认任务Map按查询响应模型补为空，不保留旧日领取数据。

日志区分共享成功、返回战报中的宠物胜利、已确认领取的任务奖励和未达标任务。三次成功不代表所有俱乐部难度任务或活跃任务均达标，自动流程只领取已达标项。

未执行真实账号攻击或领奖；当前响应体及战报覆盖范围仍待实号验证。回归使用模拟服务器状态，不冒充真实抓包。游戏更新时按《game接口定位与更新指南》重查manifest、配置、请求字段和状态模型。
