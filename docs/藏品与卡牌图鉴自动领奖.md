# 藏品与卡牌图鉴自动领奖

## 范围与使用

资源批量任务板块提供“领取藏品奖励”“领取卡牌图鉴奖励”两个独立按钮，对选中的账号执行；同时注册为可选批量任务，支持定时编排。不再提供日常设置开关，历史设置中的同名开关也不会触发日常执行。藏品包含装扮主题系列、套装属性和总积分等级奖励；卡牌包含普通/彩色卡包进度及系列集齐奖励。只领取已达标奖励，不激活装扮、不抽卡、不购买或兑换，不包含月卡/永久卡每日奖励。

## 规则与状态确认

- CollectionModule._stagesToProgress 按配置 stage 数组计算已达档位；_refreshThemedData 从 colProcess、claimProcess 读取已激活/已领奖进度。只领取 colProcess 已跨过而 claimProcess 尚未跨过的档位，不使用 canActivateNum 自动激活。
- 总积分界面以当前 collectionLevel 对应配置的下一档、claimScore >= 下一档.stage 判断可领；collectionScore 不能代替 claimScore。最高档停止，未知等级停止。
- CardPackageInfo.collectedNum 中普通卡或同位置彩卡任一拥有即可计数；collectedNum_Color 只计彩卡。对应配置 cards/colorfulCards、rewardsCardNum/rewardsCardNumColor，记录为 role.linkCardPackage[id].processClaimMap/processColorClaimMap（键为达标张数）。请求不传阈值，每次查询后继续判断剩余档位。
- CardSeriesInfo.canClaimReward/canClaimColorReward 要求所有配置 cardPackage 集齐且 role.linkCardSeries[id].claimTime/colorClaimTime 未领取。卡片持有依据 role.linkCard[id].quantity > 0。
- 这是永久收集进度，没有日重置和付费资源消耗；不根据活动 banner 结束时间排除旧图鉴，客户端仍可展示过往卡包。配置取每个账号 system_getdatabundlever 返回版本，不固定本次哈希。
- 每个账号独立读 collection_getinfo 或 role_getroleinfo 完整快照，每次领奖后重查；不以奖励返回体缺字段推断清零。进度不变立即停止。写入超时后尽力查询，停止本轮且不重发，用户停止后不补查。
- Collection_ClaimResp 声明包含 collection、继承奖励结构；SyncRewardResp 声明 role/reward。尚未连接真实账号，实际线上字段完整性与领取结果未验证，缺失关键快照字段会报错停止，不猜造返回体。

## 实现与更新

规则与执行位于 src/utils/collectionRewards.js，资源批量入口位于 src/utils/batch/tasksCollectionRewards.js；WebSocket 注册和共享响应匹配位于 xyzwWebSocket.js。测试覆盖藏品档位、主题/套装参数、彩卡替代普通卡、领取记录、账号隔离、逐次复查、进度不变、超时与停止。

游戏更新时重新请求 manifest，按 main 中当前转换和解密方式分析对应三类业务资源及账号数据配置，比较上述调用链、枚举、阈值与响应声明；不要沿用本文哈希。启动器协议变化时遵循《game接口定位与更新指南》更新入口并保留多账号桥接。
